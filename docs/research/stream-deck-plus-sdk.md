## Manifest, events, and display APIs

Dedicated actions declare `Controllers: ["Encoder"]`, one ordinary state/icon, `Encoder.layout`, and descriptions for rotate/push/touch. Use `dialRotate` signed `ticks` (positive clockwise), act on `dialUp` once per press, and guard `controller: Encoder`. The framework forwards named events and provides `setFeedback(context, payload)` and `setFeedbackLayout(context, layout)`. Its dial declarations omit controller and its action-event union omits `touchTap`; a small local typed adapter handles touch without changing the package or bypassing runtime checks.

Inherited Play/Pause and Volume Up encoder UUIDs remain aliases to preserve placed profiles. The dedicated actions have their own Encoder-only declarations; key-controller behavior is unchanged. Plugin action routing prevents the old pending-preview handler from rendering these encoders.

Use `$B1` for volume's title/icon/value/0–100 indicator. Use a bundled 200×100 custom text/pixmap layout for transport/selector, with separated name/detail/status rows. Feedback is derived from shared snapshots; cached equal renders suppress position-only messages. Short touch refreshes the current display, without a second playback activation; hold is ignored. There is no requirement for newer resource APIs or background image polling.

## OpenDeck compatibility and stack decision

Pinned OpenDeck emits `dialRotate` (signed i16 ticks), `dialUp`/`dialDown`, and `touchTap` (hold/tap position), all with Encoder controller and settings. It deserializes `setFeedback`/`setFeedbackLayout`, loads built-in/custom layouts, and applies feedback through `streamdeck_strip_render`. Custom layout paths must stay inside the plugin. Its renderer resolves image files relative to the plugin and supports pixmap sources; embedded PNG/JPEG data avoids external-file/CORS lifetime concerns. Use bounded user-provided images; no remote artwork or external path loading is introduced.

Neither the retained framework's commands nor OpenDeck's inbound command registry establishes an API to replace a host-managed Dial Stack with arbitrary configured playlist entries. `StackColor` is manifest metadata. **The reliable equivalent is one Playlist Selector encoder:** rotation changes a persisted local entry index; press dispatches that entry through the shared Stage 5 interface. It occupies one host action, rather than one host stack action per playlist, and rotates normally to select entries instead of using host stack switching. Selection/configuration is independent per context. No dynamic action registration, synthetic host stack, or fragile undocumented message is used.

HTML launching and the Stage 1 Linux-override plan remain intact. Stage 6 does not claim that canonical Windows/macOS packaging establishes native Linux installation; explicit Linux packaging remains later work. Source tracing is evidence of compatible wire behavior, not a live OpenDeck run.

## Implementation policies, assumptions, and limits

- Volume uses signed ticks × validated step (default 5) through the existing bounded confirmed-volume queue, clamped by the client. Transport sends one next/previous per tick with a bounded per-context pending count; errors/disconnect/disappearance discard unsent work, never replay it. No command waits for position ticks.
- Selector supports up to 16 named entries, canonical playlist IDs, per-entry startup modes (Follow default), and optional embedded PNG/JPEG up to 24 KiB each. Invalid saved name/ID slots are kept visible for repair and cannot execute; invalid images are ignored and old modes default to Follow. Selection is clamped/wrapped safely and survives action settings/profile restoration. Draft PI edits retain the latest incoming selection; list edits preserve position and clamp to the new bounds. Input limits are local policies, not SDK size guarantees. Image checks cover encoding/signature/size, while actual pixel decoding remains host acceptance. Normal/shuffle execution still requires the Stage 7 Pear extension.
- Layout text is bounded, while full names/metadata remain in settings/state. User title/icon overrides, glyph widths, image decoding, host write persistence, physical rotation/touch ordering, Flatpak WebView networking, and hardware readability remain manual acceptance. No real host/device/native Pear playback was tested here.
- Automated tests exercise actual browser bundles, manifest/layout structure, signed input/controller guards, press/touch separation, state mapping, queue limits/cancellation, selector persistence/edits/images, and the fake playlist contract. This verifies plugin logic and messages; source-based compatibility expectations and physical results are reported separately in the Stage 6 checkpoint. Official CLI validation covers the canonical package; no Linux override is added in this stage.
